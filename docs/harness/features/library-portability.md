# LIB-PORT-001 Экспорт и импорт раздела «Моё»

Статус: `in_progress`

Приоритет: `now`

## Решение

Добавить локальное резервное копирование всех трёх списков «Моё» в один JSON-файл и безопасное восстановление из него. Это даёт переносимость без аккаунта, сервера и синхронизации.

## Пользовательская проблема

Данные `movie-db-library-v1` привязаны к одному браузеру. Очистка данных сайта, смена телефона или браузера удаляет собранные списки, а штатного способа сохранить и перенести их нет.

## Гипотеза

Если активный пользователь сможет скачать резервную копию и импортировать её на другом устройстве, локальное «Моё» станет надёжнее без затрат и рисков серверного аккаунта. Сигнал пользы — успешное восстановление всех состояний и отсутствие повреждения текущей библиотеки при ошибочном файле.

## Scope

- Экспорт валидированного содержимого «Моё» в UTF-8 JSON с `format`, `version`, `exportedAt` и `items`.
- Импорт только после локального чтения выбранного файла и полной проверки структуры.
- Предварительный итог: сколько корректных записей найдено, сколько пропущено и что произойдёт после подтверждения.
- Два явно различимых режима: «Объединить» и «Заменить». Рекомендуемый по умолчанию — «Объединить».
- Дедупликация по `type + id`; при объединении состояния списков объединяются, а более свежая валидная карточка обновляет метаданные.
- Ограничение объёма и количества записей не слабее текущего лимита 500 элементов.

## Не входит

- Автоматическая синхронизация, облачное хранилище, аккаунт и отправка файла на сервер.
- Импорт CSV, Letterboxd, Кинопоиска или других внешних форматов.
- Экспорт темы, истории поиска, фильтров, ключа TMDB или настроек PWA.
- Фоновое резервное копирование.

## UX-сценарий

1. В разделе «Моё» пользователь открывает «Резервная копия».
2. «Скачать» создаёт файл `moviedb-library-YYYY-MM-DD.json` локально в браузере.
3. Для импорта пользователь выбирает файл; сайт читает его локально и показывает безопасный итог до записи.
4. Пользователь выбирает «Объединить» или «Заменить» и отдельно подтверждает действие.
5. После записи раздел «Моё» обновляется, а URL и выбранная вкладка сохраняются.
6. Невалидный файл ничего не меняет и может быть выбран повторно.

## Данные и ограничения

Текущий storage key — `movie-db-library-v1`; библиотека уже нормализует тип, ID, строки, изображения, рейтинг, состояния и `updatedAt`. Экспорт должен использовать тот же публичный нормализатор, но иметь собственную версию формата, не зависящую от имени storage key.

Выбранный пользователем файл читается File API в браузере и не отправляется MovieDB. До изменения localStorage весь файл парсится во временную структуру. Размер файла ограничивается до чтения/парсинга; неожиданно большие или вложенные данные отклоняются.

## Состояния

- Loading: короткое состояние чтения/проверки файла.
- Content: сводка импорта и выбор режима.
- Empty: пустая текущая библиотека экспортируется только после пояснения либо кнопка отключена; валидный импорт с нулём элементов ничего не меняет.
- Error: неверный JSON, версия, размер или отсутствие хранилища объясняются без технического стека.
- Retry: выбрать другой файл.
- Offline: экспорт и импорт полностью работают без сети.

## Критерии готовности

- Экспорт не содержит ничего кроме версии, даты и нормализованных элементов «Моё».
- Экспортированный файл импортируется обратно без потери трёх независимых состояний.
- Невалидный или частично повреждённый файл не повреждает текущую библиотеку.
- «Объединить» не создаёт дубликаты; «Заменить» требует отдельного подтверждения.
- Старые поддерживаемые версии мигрируют явно, неизвестные версии отклоняются.
- Работа не требует сети или внешнего сервера.

## Проверки

- Unit-тест round trip, дедупликации, merge/replace, лимитов и миграции версии.
- Fuzz-набор: неверный JSON, массив вместо объекта, неизвестная версия, лишние поля, опасные URL, 501+ элемент и слишком большой файл.
- Проверка атомарности: ошибка перед записью оставляет старое значение неизменным.
- Ручная проверка скачивания и выбора файла в Safari iOS/macOS и Chromium.
- Реальный перенос файла между двумя чистыми браузерными профилями.

## Риски и откат

Главный риск — необратимая потеря списка при режиме «Заменить». До подтверждения можно автоматически сохранить предыдущий JSON в памяти/файле либо настойчиво предложить экспорт. Откат UI не должен удалять уже импортированные валидные данные.

Стоп-условие: нет подтверждения реального использования «Моё» или мобильный Safari не обеспечивает понятный файловый сценарий для целевой аудитории.
