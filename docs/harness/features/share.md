# SHARE-001 Поделиться карточкой и подбором

Статус: `in_progress`

Приоритет: `now`

## Решение

Сделать существующие URL-состояния видимой функцией: добавить действие «Поделиться» в карточку и рядом с результатами поиска/подбора. На поддерживаемых устройствах открывается системное меню, в остальных случаях ссылка копируется.

## Пользовательская проблема

Прямые ссылки уже работают, но пользователь должен догадаться скопировать адресную строку. На телефоне это неудобно, а получатель не понимает заранее, отправлен конкретный фильм или набор фильтров.

## Гипотеза

Если дать одно явное действие, пользователь сможет за один-два шага отправить конкретное название или свой подбор. Сигнал пользы — успешное системное действие или копирование ссылки без потери состояния после открытия получателем.

## Scope

- Кнопка в карточке делится каноническим текущим URL, названием и коротким нейтральным текстом.
- Кнопка в каталоге делится URL текущего поиска, «Подбора», списка или раздела «Моё» без локального содержимого.
- `navigator.share()` вызывается только после пользовательского нажатия, если доступен.
- Fallback копирует URL через Clipboard API; при его недоступности показывает выделяемое поле/диалог с готовой ссылкой.
- После успеха или отмены пользователь остаётся на том же экране; ненавязчивый статус озвучивается через live-region.

## Не входит

- Серверные короткие ссылки, QR-коды, Open Graph-превью и учёт получателей.
- Автоматическое раскрытие содержимого локального «Моё»: ссылка передаёт только `mode=my` и выбранную вкладку, потому что сами записи хранятся на устройстве.
- Отправка в конкретную соцсеть отдельной интеграцией.
- Сбор контактов или аналитики получателя.

## UX-сценарий

1. Пользователь нажимает «Поделиться» в карточке или каталоге.
2. Если Web Share доступен, браузер открывает системное меню. Если нет — копируется ссылка.
3. Интерфейс сообщает «Ссылка скопирована» либо спокойно остаётся без сообщения при отмене системного меню.
4. Получатель открывает HTTPS-ссылку и видит тот же публично воспроизводимый фильтр/карточку.
5. Back/Forward, refresh и повторное нажатие не меняют состояние каталога.

## Данные и ограничения

Web Share работает только в secure context, поддерживается не всеми браузерами и требует пользовательской активации. Поэтому системное меню — улучшение, а не единственный путь.

Перед отправкой URL строится существующим `stateUrl`, чтобы в него не попадали случайные/невалидные параметры. Локальный список и тема не сериализуются. Текст карточки берётся из уже загруженных нормализованных данных, а не из HTML.

## Состояния

- Loading: не нужен; подготовка URL локальная.
- Content: обычная кнопка с доступным названием.
- Empty: в каталоге без воспроизводимого состояния можно поделиться корневым URL.
- Error: короткое сообщение и доступное поле со ссылкой.
- Retry: повторное нажатие или ручное копирование.
- Offline: уже открытый URL можно скопировать; системное приложение получателя решает отправку самостоятельно.

## Критерии готовности

- Карточка отправляет URL с валидными `view` и `id`.
- «Подбор» отправляет выбранные тип, жанры, период, оценку, сортировку и страницу.
- Получатель после refresh видит тот же публичный экран.
- «Моё» не обещает передачу локальных записей между устройствами.
- Отмена Web Share не показывается как ошибка.
- Кнопка доступна клавиатурой и не ломает раскладку на iPhone.

## Проверки

- Unit-тест состава share payload и очистки URL.
- Тест трёх веток: Web Share, Clipboard и ручной fallback.
- Тест отмены (`AbortError`) и реальной ошибки.
- Ручная проверка Safari iOS/macOS и Chromium по HTTPS, включая PWA с домашнего экрана.
- Открытие полученной ссылки в новой приватной вкладке без localStorage отправителя.

## Риски и откат

Риски: разная поддержка API, вводящее в заблуждение «Моё» и слишком длинные URL фильтров. Функция изолирована в одной кнопке и helper-модуле; её можно убрать без миграции данных.

Стоп-условие: ссылка не воспроизводит состояние после refresh или основной браузер аудитории не получает надёжный fallback.

Локально проверено:

- `npm run check`, `npm test` (22 теста) и `git diff --check` завершены успешно.
- Автотесты покрывают Web Share, Clipboard и ручной путь, отмену, отказ браузера, привязку методов API и вызов Web Share до любого ожидания.

- В проверенной новой вкладке нет предупреждений или ошибок консоли.

Остаётся до `verified`: системная отправка и её отмена в реальном Safari iOS/macOS и Chromium по HTTPS, PWA с домашнего экрана и без сети, получатель в приватной вкладке.
