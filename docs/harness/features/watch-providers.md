# PROVIDERS-001 Где смотреть

Статус: `researched`

Приоритет: `research`

## Решение

Проверить качество региональных данных TMDB/JustWatch на целевых странах и только после этого решить, добавлять ли в карточку блок «Где смотреть». Первая версия не обещает прямой переход в конкретный видеосервис.

## Пользовательская проблема

После выбора фильма или сериала пользователь не знает, на какой площадке он доступен легально в его стране, и вынужден искать это отдельно. Текущий MovieDB заканчивает путь раньше практического действия «начать смотреть».

## Гипотеза

Если в карточке честно показать доступные по данным источника варианты подписки, аренды или покупки для выбранной страны, пользователю потребуется меньше внешнего поиска. До разработки нужно подтвердить покрытие: пустые или устаревшие ответы принесут больше разочарования, чем пользы.

## Scope

- Исследовательская выборка минимум из популярных, новых и старых фильмов/сериалов для каждой утверждённой страны.
- После успешной проверки — запрос `/movie/{movie_id}/watch/providers` или `/tv/{series_id}/watch/providers`.
- Явно выбранная страна с понятным значением по умолчанию; она не определяется скрыто по персональным данным.
- Группы `flatrate`, `rent`, `buy` только при наличии; логотип, название площадки и обязательная атрибуция JustWatch.
- Ссылка, предоставленная ответом TMDB, с честной подписью; не выдавать её за гарантированный deep link в приложение площадки.
- Дата/оговорка об изменчивости доступности и возможность повторить запрос.

## Не входит

- Собственный парсинг сайтов видеосервисов, обход геоограничений и гарантия наличия конкретной озвучки.
- Цены, промокоды, партнёрские выплаты и ранжирование за деньги.
- Определение страны по IP без отдельного решения о приватности.
- Уведомления о появлении фильма, потому что для них нужны серверное наблюдение и push-инфраструктура.

## UX-сценарий

1. Пользователь открывает карточку и видит выбранную страну рядом с блоком «Где смотреть».
2. Блок показывает доступные группы по данным источника или честное отсутствие сведений.
3. Пользователь может сменить страну; выбор сохраняется локально, но не меняет URL карточки без отдельного решения.
4. Нажатие ведёт по ссылке, предоставленной TMDB, в новой вкладке/приложении с безопасными атрибутами.
5. Возврат сохраняет карточку и позицию; ошибка провайдеров не блокирует сведения, трейлер и «Моё».

## Данные и ограничения

TMDB предоставляет региональные данные просмотра от JustWatch для фильмов и сериалов. Документация требует атрибуцию JustWatch и указывает, что ответ содержит ссылку TMDB, а не полные deep links на отдельные сервисы. Доступ может быть изменён или отозван при несоблюдении условий.

Данные зависят от страны и меняются независимо от MovieDB. Нужна отдельная проверка для реальной аудитории проекта; технически непустой ответ не доказывает фактическую доступность. Логотипы и названия проходят существующие ограничения внешних ресурсов.

## Состояния

- Loading: локальный индикатор внутри блока, не блокирующий карточку.
- Content: страна, тип доступа, площадки, атрибуция и оговорка актуальности.
- Empty: «У источника пока нет данных для выбранной страны», без вывода «нигде не доступно».
- Error: нейтральное сообщение и повтор только этого запроса.
- Retry: повторяет запрос провайдеров.
- Offline: блок сообщает, что для обновления нужна сеть; основные локальные функции остаются доступны.

## Критерии готовности

- До разработки составлена таблица покрытия по утверждённым странам и типам контента.
- Для фильмов и сериалов используются правильные endpoints и регион.
- Empty не трактуется как доказательство отсутствия фильма во всех сервисах.
- Атрибуция JustWatch видна рядом с данными и соответствует требованиям источника.
- Пользователь понимает разницу подписки, аренды и покупки.
- Ошибка блока не ломает карточку и не создаёт горизонтальный скролл на iPhone.

## Проверки

- Исследовательская выборка с ручной сверкой части ответов для каждой страны.
- Unit-тест нормализации регионов, групп, дубликатов и отсутствующих логотипов.
- Тест endpoints `movie`/`tv`, смены страны и отмены устаревшего запроса.
- Проверка ссылок, атрибуции, клавиатуры и screen-reader названий.
- Desktop Safari/Chromium и реальный iPhone Safari, включая новую вкладку и возврат в PWA.

## Риски и откат

Риски: недостоверное обещание, слабое покрытие страны, устаревшие данные и нарушение условий атрибуции. Блок должен быть независимым и выключаться одним feature flag/удалением вызова без изменения карточки и localStorage.

Стоп-условие: для целевой страны покрытие недостаточно, источник не разрешает нужную подачу или пользовательский тест воспринимает список как гарантию доступности.

## Решение Алексея

Статус решения: `required`

Сначала нужно утвердить страны исследования и допустимую формулировку ограничения. Решение о реализации принимается только после таблицы покрытия и проверки требований атрибуции.

После решения записать дату и точную формулировку. До этого интерфейс не реализовывать.
