# Сценарии проверки

Это повторяемые сценарии, а не отчёт об их прохождении. Для нового пакета в [EVIDENCE.md](EVIDENCE.md) отмечать по каждому применимому ID: дату, commit или загруженную версию, URL, окружение (браузер/устройство/iOS/режим PWA), результат `pass` / `fail` / `not_run` и краткое доказательство. Эмуляция ширины и Playwright WebKit полезны, но не заменяют физический Safari на iPhone. При изменении данных проверять на тестовой копии, не на единственном личном списке.

| ID | Действие и ожидаемый результат | Где обязательно проверять |
| --- | --- | --- |
| S-01 | «Не знаю название» → Подбор с типом, жанрами, периодом, рейтингом и страницей → карточка → рекомендация → Back дважды. Фильтры, страница, исходная карточка и положение восстанавливаются. | Автотест URL; браузер; физический iPhone |
| S-02 | Открыть прямую ссылку на поиск, список, детали и `?mode=lists&list=one-evening`; обновить страницу, пройти Back/Forward. Нет чужого экрана и потерянного состояния. | Браузер и iPhone |
| S-03 | Отдельно проверить `loading`, пустой ответ, ошибку, `retry`, отмену устаревшего запроса, длинный заголовок и отсутствие постера. Старый ответ не заменяет новый. | Автотест; браузер, если есть UI |
| S-04 | В «Моё» отметить позже, избранное и просмотрено независимо; обновить страницу. Данные остались, прочие отметки не изменились. | Автотест; Safari; PWA |
| S-05 | Скачать копию и убедиться в реальном файле; перенести его в другой контекст, увидеть предпросмотр, объединить и повторить импорт без дублей. Все три отметки сохраняются. | Safari и установленная PWA на физическом iPhone |
| S-06 | Ошибочный/пустой импорт, отказ хранилища и замена на тестовом наборе не уничтожают исходные списки; предыдущая версия реально сохраняется до закрытия страницы. | Автотест; физический iPhone для сохранения файла |
| S-07 | Поделиться подбором и карточкой; получатель открывает тот же экран. Отмена системного меню не вызывает ошибку. Пиктограмма имеет доступную подпись и видимый фокус. | Браузер; физический iPhone Safari/PWA |
| S-08 | Узкая и широкая ширина, обе темы, ориентации, safe area, Tab/Enter и экранная клавиатура. Нет перекрытых действий и горизонтального скролла. | Браузер и физический iPhone |
| S-09 | Установить PWA, открыть с сетью, отключить сеть и перезапустить. Оболочка и «Моё» доступны; новые данные TMDB могут быть недоступны, что объяснено пользователю. Затем вернуть сеть и повторить запрос. | Физический iPhone в установленном режиме |
| S-10 | Обновить старую оболочку до новой без удаления PWA и очистки данных сайта. Списки остаются, версии локальных файлов согласованы, прежняя вкладка не ломается. | Автотест версий; браузер; физический iPhone перед заявлением о приёмке |
| S-11 | После разрешённой публикации сравнить commit `master`, результат Pages, реально загруженную версию файлов и публичный сценарий. Не считать успешную сборку проверкой интерфейса. | GitHub Pages и публичный HTTPS-сайт |

## Отдельно о хранилище Safari и PWA

При проверке S-05 и S-09 заранее записать, где создан тестовый список: в Safari или в приложении с главного экрана. Если хранилища изолированы, перенос идёт через файл; нельзя объявлять отсутствие автоматической синхронизации дефектом или обещать её пользователю. Перед любым обновлением сохранить резервную копию; для сброса кэша никогда не очищать все данные сайта.

## Как применять к инициативам

- REC-001: S-01, S-02, S-03, S-08; согласованная iPhone-проверка возврата и скролла уже записана в [EVIDENCE.md](EVIDENCE.md).
- SHARE-001: S-02, S-07, S-08, S-09.
- LIB-PORT-001: S-04, S-05, S-06, S-09, S-10.
- EDIT-001: S-01, S-02, S-03, S-08, S-09.
- PROVIDERS-001: UI-сценарии не применяются, пока не принято решение о реализации после проверки данных.

Новые кандидаты получают собственные дополнительные случаи только после утверждения scope. Для документационного изменения этого харнеса физические сценарии не объявляются выполненными.
