# Устройство и публикация сайта

## Структура

Сайт состоит из статических файлов и выполняется в браузере без сборки:

- `index.html` — разметка поиска, подбора, списков и карточки;
- `main.css` — темы, адаптивная сетка и оформление компонентов;
- `fetchscript.js` — взаимодействия, загрузка данных и отрисовка;
- `state.js` — разбор и создание адресов, параметры текущего состояния;
- `tmdb.js` — запросы к TMDB и приведение ответов к данным интерфейса;
- `tests/site.test.mjs` — проверки URL, запросов, обработки данных и ошибок.

`script.js` остался от прежней версии сайта и не подключён в новом `index.html`.

## Данные и адреса

Поиск использует `/search/movie`, `/search/tv` или `/search/multi`. Подбор использует `/discover/movie` или `/discover/tv`. Восемь готовых списков обращаются к соответствующим `/trending`, `/movie/*` и `/tv/*` маршрутам TMDB. Карточка запрашивает детали по типу и ID, а трейлер выбирается из доступных YouTube-видео.

Выбранные условия, список и страница хранятся в параметрах URL. Старые ссылки с одним `genre` продолжают разбираться; новые используют `genres`. Фильтр нескольких жанров передаёт TMDB список ID через запятую, что означает совпадение всех жанров. Запросы отменяются при смене режима, страницы или карточки; каталог кешируется в памяти вкладки.

При отсутствии данных сайт показывает пустое состояние или сообщение об ошибке с повторным запросом. При отсутствии постера используется локальное изображение. Трейлер встраивается только после нажатия пользователем кнопки просмотра.

## Ограничения источника

- Порядок жанров вычисляется по текущей загруженной порции результатов, поэтому не является глобальной статистикой популярности TMDB.
- Некоторые жанры сериалов TMDB объединяет в один ID, например «Боевик и Приключения». Интерфейс показывает отдельные названия, но фильтрация для них опирается на общий ID: она не может различить эти поджанры по данным TMDB.
- Результаты, оценки, даты, переводы и трейлеры меняются на стороне TMDB. Сайт не гарантирует их полноту и не хранит копию каталога.
- Ключ TMDB используется непосредственно в браузерных запросах. Он виден посетителю статического сайта и не должен рассматриваться как секрет. При появлении лимитов или злоупотреблений потребуется отдельное решение о прокси и ключе на сервере.

## Проверки и выпуск

`npm run check` проверяет синтаксис JavaScript, `npm test` запускает тесты без сетевых запросов. Перед публикацией также нужны ручные проверки поиска, фильтра нескольких жанров, списков, карточки, светлой и тёмной тем и узкого экрана.

GitHub Pages читает корень ветки `master`; отдельной сборки и workflow нет. После слияния изменений нужно дождаться успешной сборки Pages и открыть публичный адрес, чтобы отдельно подтвердить реальную публикацию. Локальный сервер или зелёные тесты не доказывают, что публичная версия обновилась.

В браузере сохраняется только выбор темы в `localStorage`. Аккаунтов и хранения пользовательских поисковых запросов на своём сервере нет. Запросы каталога уходят напрямую в TMDB; запрос трейлера — к YouTube после действия пользователя.
