# Анимация — Variant 3

Источник: [Google Doc](https://docs.google.com/document/d/15En30HOCVZT0e6zjNZSI6btNmhE3ZVsOHNgbB8di60I/edit). Снимок документа от 2026-09-30; этот файл — локальная копия для разработки.

**Текущий статус:** направление анимации относится к выбранному Variant 3; финальный визуальный макет ещё в разработке. Конкретные эффекты следует сверить с завершённым макетом. См. [manifest.json](manifest.json).

Цель: сделать Variant 3 живым, современным и визуально богатым, не превращая сайт в аттракцион.


## 1. Общий характер
- Motion: плавный, уверенный, немного кинематографичный.
- Избегать «пружинок на всём», постоянного покачивания и одинаковых reveal-анимаций для каждого блока.
- Ритм должен меняться: hero выразительнее, контентные секции спокойнее, CTA быстрее.


## 2. Motion tokens
Fast feedback: 90-140 ms.
Hover / small state change: 160-220 ms.
Buttons/cards enter-exit: 220-320 ms.
Section reveal: 400-650 ms.
Hero intro: 550-900 ms, элементы могут иметь stagger 50-100 ms.
Не делать длинные обязательные последовательности, которые задерживают доступ к контенту.


Базовые easing-направления:
- UI feedback: ease-out / cubic-bezier с быстрым стартом и мягким торможением.
- Entrance: мягкий ease-out.
- Exit: немного быстрее entrance.
- Декоративный ambient motion: очень медленный и малой амплитуды.


## 3. Page load
- Header появляется без тяжёлой постановки.
- Hero: заголовок, supporting content и CTA могут входить последовательно с небольшим stagger.
- Начальное смещение небольшое, ориентир 8-20 px.
- Одновременно не анимировать весь viewport.
- LCP-элемент не прятать до завершения длинной анимации.


## 4. Scroll reveal
- Intersection-based, один раз для большинства контентных блоков.
- Opacity + небольшое translate.
- Для крупных секций возможна анимация дочерних элементов со stagger.
- Не анимировать каждую строку текста.
- Не использовать скролл как жёсткую временную шкалу, которая перехватывает управление.


## 5. Parallax / depth
- Только декоративные элементы и медиа, не основной текст.
- Небольшая амплитуда.
- На mobile уменьшить или отключить.
- Никакого layout reflow на каждом scroll event.


## 6. Buttons
Hover-capable devices:
- лёгкая реакция поверхности/границы/контраста;
- небольшое translate или scale допускается, но без скачка layout;
- 160-200 ms.
Press:
- быстрое физическое подтверждение 90-120 ms.
Focus-visible:
- отдельное явно читаемое состояние, не заменять hover-анимацией.


## 7. Cards
- Hover: небольшое elevation/depth изменение.
- Допускается минимальный tilt только при наличии реальной визуальной пользы; не делать стандартом для всех карточек.
- Изображение может иметь лёгкий внутренний zoom, но не должно обрезать важный контент.
- На touch hover-эффекты отключаются.


## 8. Navigation
- Mobile menu открывается быстро и не заставляет ждать.
- Background overlay и panel могут иметь разную скорость, но суммарно интерфейс должен ощущаться мгновенным.
- Закрытие немного быстрее открытия.
- Состояние текущего раздела не зависит только от анимации.


## 9. Hero ambient motion
Разрешено 1-2 заметных «живых» слоя:
- плавное смещение декоративной формы;
- мягкое изменение градиента/свечения;
- реакция на pointer только desktop и только если не мешает CTA.
Не делать одновременно частицы + мощный parallax + cursor trail + WebGL + video background. Один сильный приём лучше пяти конкурирующих.


## 10. Section transitions
- Между секциями допустимы маски, clip-path, reveal или небольшая depth-смена.
- Использовать выборочно для 2-3 ключевых переходов, а не между всеми секциями.
- На слабых устройствах эффект должен деградировать до простого opacity/translate.


## 11. Reduced motion
При prefers-reduced-motion: reduce:
- отключить parallax, pointer-follow, крупные translate/scale, looping motion;
- оставить мгновенные или короткие opacity-state изменения, если они помогают понять интерфейс;
- не удалять контент и функциональность;
- никакой зависимости UX от движения.


## 12. Производительность
- По возможности transform и opacity.
- Не анимировать width/height/top/left для крупных элементов во время непрерывного взаимодействия.
- Не создавать десятки одновременно активных observers/listeners без необходимости.
- requestAnimationFrame для непрерывного JS-motion.
- Lazy-load offscreen media.
- Уважать реальный device capability и отключать дорогие эффекты на mobile/low-power при необходимости.


## 13. QA motion
Проверить:
- 60fps-ощущение на типичном современном телефоне, без явных фризов.
- Быстрый scroll туда-сюда.
- Открытие/закрытие меню многократно.
- Reduced Motion.
- Keyboard-only.
- Touch без hover.
- Resize / orientation change.
- Back/forward navigation.
- Slow network и повторное появление изображений.


## 14. Definition of Done
Motion считается готовым, если:
- он усиливает Variant 3;
- нет ощущения шаблонного fade-up на каждом элементе;
- ни один эффект не мешает главному CTA;
- mobile остаётся быстрым;
- reduced-motion полноценен;
- Core Web Vitals не ухудшились из-за motion.
