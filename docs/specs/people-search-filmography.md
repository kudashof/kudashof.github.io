# ТЗ: живой поиск, люди кино и расширенная карточка в MovieDB

Дата: 12 октября 2026 года.

Редакция 2: добавлены подсказки и автоматический поиск без кнопки, основные сведения о фильме/сериале, слоган и компактный блок дополнительных данных по трём пользовательским референсам.

Статус: подготовлено для будущей реализации. Создание этого ТЗ не разрешает автоматически реализацию или публикацию. Дизайн новых экранов и обновлённой карточки пока не утверждён; описанная ниже компоновка — рекомендуемое направление для макетов.

Связь с проектом: CAND-008 «Люди кино», существующий поиск и карточка произведения. Расширяет опубликованный CAST-001 — фотографии актёров и режиссёров в карточке фильма/сериала. Не заменяет существующий состав. Имя файла сохранено для совместимости с предыдущей передачей ТЗ.

## 1. Цель

Помочь выбрать следующий фильм или сериал через знакомого актёра или режиссёра:

1. Нажать на человека в составе фильма/сериала или найти его по имени в общей поисковой строке.
2. Открыть страницу человека с реальным фото и фильмографией TMDB.
3. Переключаться между отдельными списками фильмов и сериалов.
4. Открыть выбранную работу, добавить её в существующее «Моё» и вернуться без потери контекста.

Первая версия включает оба входа: переход из состава и поиск по имени. Поиск людей не откладывается на следующий выпуск.

Дополнительные цели: находить названия по части слова с подсказками и автоматической выдачей; видеть страну, жанры и длительность сразу в карточке; получать слоган и второстепенные сведения без перегрузки основного сценария выбора.

## 3. Пользовательские сценарии

### 3.1. Из состава

- Фото и имя актёра становятся одной понятной ссылкой на страницу человека; исходная роль персонажа остаётся видимой.
- Аналогично работает фото и имя режиссёра.
- Нажатие на актёра открывает режим «В ролях», на режиссёра — «Режиссура».
- Раскрытие полного состава продолжает работать; ссылка на человека не должна случайно сворачивать список.
- После открытия работы из фильмографии возврат ведёт к тому же человеку, вкладке, сортировке, раскрытому объёму списка и месту прокрутки. Следующий возврат ведёт в исходную карточку и сохраняет контекст каталога.

### 3.2. По имени

- Использовать существующую поисковую строку в режиме «Поиск».
- Добавить категорию «Люди» рядом с текущими категориями названий. Для ясности текущую категорию «Всё» назвать «Все названия»: она по-прежнему объединяет фильмы и сериалы.
- Пользователь выбирает «Люди» и вводит имя; подсказки и выдача обновляются автоматически по правилам раздела 4. Автоматически угадывать тип запроса не требуется.
- В категории «Люди» label/placeholder: «Имя актёра или режиссёра»; пояснение: «Поиск людей по данным TMDB». В категориях названий сохраняются соответствующие подсказки.
- Смена категории сохраняет введённый запрос и сбрасывает страницу выдачи. Не смешивать карточки людей и постеры названий в одну сетку.
- Видимую кнопку «Поиск» убрать в режиме текстового поиска. Enter остаётся дополнительным способом сразу применить запрос или открыть выбранную подсказку. Кнопка подбора по фильтрам относится к другому сценарию и не удаляется автоматически.
- Поддержать пагинацию TMDB и её текущий паттерн в MovieDB. Пустой запрос не отправлять.

### 3.3. Прямая ссылка

Поиск людей, страница человека и выбранная вкладка открываются после перезагрузки и по отправленной ссылке. Для GitHub Pages использовать query-параметры, чтобы новый путь не приводил к 404.

## 4. Живой поиск и автодополнение

### 4.1. Поведение

- Одна поисковая строка и текущие категории «Все названия / Фильмы / Сериалы / Люди».
- После ввода минимум двух символов очищенного запроса выполнить поиск через 350 мс после последнего изменения. Значения — стартовые настройки для проверки, допускается небольшая корректировка по результатам QA.
- Одним ответом первой страницы обновлять основную выдачу и список до шести подсказок под полем. Не отправлять два одинаковых запроса отдельно для подсказок и каталога.
- Для «инте» показывать реальные совпадения TMDB, например «Интерстеллар», «Интервью». Не фиксировать этот набор в коде и не обещать неизменный порядок сервиса.
- Подсказка названия: небольшой постер, название, год и тип «Фильм»/«Сериал». Подсказка человека: фото, имя, профессия и краткая известная работа, если есть. Без рейтингов, длинных описаний и лишних кнопок.
- Нажатие на подсказку открывает соответствующую карточку. Пользователь может продолжить ввод и пользоваться полной выдачей без выбора подсказки.
- Основной обязательный паттерн — выпадающие варианты. В макете дополнительно проработать ненавязчивый остаток первого подходящего названия прямо в поле: введённое «Инте» + визуальная подсказка «рстеллар». Это только для буквального совпадения начала строки, без замены набранного текста, выдуманной транслитерации и вмешательства в редактирование. Вариант внутри поля согласовать по макету; если он мешает мобильному вводу, использовать на телефоне список под строкой.
- Текст пользователя не дополняется сам. Если реализована подсказка остатка, принять её можно явным действием, например ArrowRight в конце строки на компьютере; обычный Tab сохраняет стандартный переход фокуса.
- Смена категории сохраняет query и запускает новый поиск сразу при достаточной длине. Страница выдачи сбрасывается на первую, ответы прежней категории игнорируются.
- При двух и более символах Backspace также обновляет результаты с debounce. При одном символе отменить запрос, закрыть варианты и показать «Введи ещё один символ»; не показывать предыдущие результаты как соответствующие новому запросу. После очистки — исходное пустое состояние режима «Поиск», без сетевого запроса.
- Enter без выбранного варианта немедленно применяет запрос, минуя оставшуюся задержку, закрывает подсказки и оставляет полную выдачу; не дублирует уже выполняющийся запрос. Enter при активной подсказке открывает её.
- Escape закрывает варианты без удаления query. Клик/тап вне поля закрывает их, но не запускает поиск повторно. При повторном фокусе варианты можно открыть из актуального кеша.

### 4.2. Сеть, состояние и история

- `/search/movie`, `/search/tv`, `/search/person` или существующий `/search/multi` для всех названий; `language=ru-RU`, `include_adult=false`. Из multi в этой категории исключать людей, сохраняя отдельный режим поиска людей. Не выдавать сырой total_results смешанного multi за точное количество только названий.
- Подсказки используют первую страницу ответа выбранной категории; их лимит не ограничивает полную выдачу. Сохраняется пагинация полной выдачи.
- Отменять таймер и запрос при новом вводе, смене категории, очистке и уходе. Дополнительно проверять актуальность ответа по query, категории, странице и последовательности запроса.
- Во время composition/IME не отправлять незавершённый ввод; начинать debounce после compositionend. Работают вставка текста, мобильная клавиатура, пробелы, кириллица и латиница.
- Ограниченный кеш и объединение запросов в работе по ключу «категория + query + страница + язык». Ошибки не кешировать как пустую успешную выдачу. Возврат к недавнему запросу не создаёт лишних одинаковых запросов.
- Не менять URL на каждую букву и не добавлять запись browser history на каждую автоматическую выдачу. Хранить draft отдельно, а применённый query обновлять через replaceState только в маршруте поиска. Перед уходом в карточку сохранить актуальный контекст поиска; переход в карточку создаёт отдельный шаг истории. Back/Forward и прямые ссылки остаются предсказуемыми.
- Во время ожидания новая выдача не должна выдавать старые результаты за совпадения нового query. Допустимо сохранить прежнюю сетку с явным состоянием обновления, затем заменить её; не перехватывать фокус и не прокручивать страницу при каждом ответе.
- Ошибка/429/недоступность: понятное сообщение и «Повторить», без бесконечных автоматических повторов и потери ввода. Отсутствие результатов — отдельное состояние.

### 4.3. Десктоп, телефон и доступность

- Combobox с доступным label, `aria-expanded`, `aria-controls`, `aria-autocomplete=list` (либо `both` при согласованном дополнении внутри поля), listbox/option и `aria-activedescendant` для активного варианта. В DOM-фокусе остаётся input; список не содержит вложенных независимых интерактивных кнопок.
- ArrowDown/ArrowUp меняют активный вариант; Enter выбирает; Escape закрывает; Tab переносит фокус по странице. Объявлять завершение поиска через спокойный live region, а не озвучивать каждую букву и все карточки.
- На телефоне варианты расположены под строкой, имеют удобные зоны касания не менее 44 × 44 CSS px и остаются достижимыми с открытой клавиатурой. Ограничить высоту списка по доступному viewport и дать прокрутку, не закрывать всю страницу.
- На десктопе dropdown привязан к ширине поля, имеет корректный слой над контентом и не обрезается overflow родителя. Никаких действий только по hover.
- Не использовать один placeholder вместо label; введённый текст остаётся читаемым в обеих темах. Нативное редактирование, выделение, стрелки и горизонтальная прокрутка длинного текста не ломаются из-за подсказки внутри поля.

## 5. Выдача людей и однофамильцы

Карточка результата содержит:

- Фото TMDB или существующую по стилю заглушку «Нет фото».
- Имя из источника.
- Основное направление деятельности, если TMDB его указал: например, «Актёр», «Режиссёр». Не выводить profession как доказательство конкретной режиссёрской работы.
- До трёх названий известных работ из `known_for`, чтобы различать однофамильцев. Сохранить различие фильма и сериала.
- Понятный переход на страницу выбранного человека по `person_id`.

Не объединять людей по совпадению имени и не выбирать первый результат автоматически. Для идентичности использовать только TMDB ID.

Если фото, профессия или известные работы отсутствуют, оставить доступную карточку без выдуманных данных. Не делать отдельный запрос деталей на каждого человека в выдаче только ради возраста или места рождения. TMDB может вернуть представителей других профессий: не отбрасывать их только по `known_for_department`, поскольку человек может работать в нескольких ролях. На странице честно показывать доступность поддерживаемых разделов.

## 6. Страница человека: рекомендуемый дизайн

### 6.1. Шапка

- Кнопка возврата с понятной подписью по контексту: «К результатам поиска» или «К фильму/сериалу».
- Реальное фото, имя и подпись выбранного направления.
- При наличии обоих видов работ — переключатель «В ролях / Режиссура». Если доступно только одно направление, переключатель не нужен.
- Длинное имя переносится; фото не растягивается и не блокирует загрузку страницы.
- Биография, награды, возраст, родственники и ссылки на соцсети не входят в первую версию.

### 6.2. Два списка

- Вкладки «Фильмы · N» и «Сериалы · N»: это два независимых набора, без смешанной ленты.
- По умолчанию открывать фильмы; если фильмов нет, а сериалы есть — сериалы. Прямой URL и восстановленная история имеют приоритет.
- Счётчик — число уникальных работ в выбранном направлении после действующих фильтров, а не число сырых записей API.
- Переключение вкладки сохраняет её прокрутку и число показанных карточек в рамках текущей страницы человека. Новая сортировка или фильтр сбрасывают объём показанного списка и прокрутку к его началу.
- Сортировка общая для обеих вкладок: «Популярные», «Новые», «По рейтингу». Начальное значение — «Популярные».
- Для большой фильмографии использовать порционное раскрытие «Показать ещё»: первая порция 12 карточек, следующие по 12. API фильмографии возвращает набор целиком; раскрытие относится к отображению, а не выдуманной серверной пагинации.
- На компьютере использовать существующую адаптивную сетку карточек. На телефоне — две карточки в ряд, вкладки и элементы управления без горизонтального переполнения.

### 6.3. Карточки работ

Использовать текущие карточки фильма/сериала: постер, название, год, рейтинг и существующие действия «Моё», если они предусмотрены этим компонентом. Нажатие открывает обычную карточку работы.

Добавить строку участия:

- Для актёрских работ — персонаж/озвучка из TMDB. Не переводить роли моделью и не удалять пометки об озвучке. Несколько ролей объединять и аккуратно сокращать визуально без потери доступного текста.
- Для фильма в режиссёрском режиме — «Режиссёр».
- Для сериала — «Режиссура эпизодов»: не представлять участие в части эпизодов как постановку всего сериала. Точное число эпизодов не обязательно для первой версии; не суммировать его наивно при повторных credit-записях.
- Будущая дата выхода — пометка «Скоро». Отсутствующий год — без выдуманной даты. Отсутствующий рейтинг — «Нет оценки», а не убедительная нулевая оценка.

## 7. Расширенная карточка фильма и сериала

### 7.1. Референсы и иерархия

Пользовательские изображения — визуальные примеры структуры, а не источник истинных данных или инструкция скопировать чужую тему:

1. [Основная строка сведений](refs/detail-main-facts.png): возрастной сертификат, дата/регион релиза, жанры и длительность.
2. [Слоган перед описанием](refs/detail-tagline.png): выделенный текст в примере — вероятнее всего tagline, то есть рекламный слоган, а не подтверждённая реплика персонажа. Для MovieDB источником служит поле `tagline`.
3. [Второстепенные сведения](refs/detail-secondary-facts.png): исходное название, статус, исходный язык, бюджет и сборы.

Расширять полную карточку произведения. Маленькие карточки каталога, подсказок и фильмографии не перегружать всеми этими полями и не обогащать отдельными detail-запросами на каждый постер.

Порядок основных элементов: заголовок → компактные основные сведения → текущий рейтинг и действия → слоган → описание → существующий состав и трейлер. Сохранить удобство имеющихся действий и их утверждённую иерархию. Второстепенные сведения размещаются ниже основной информации, отдельным сворачиваемым блоком «Подробнее о фильме» / «Подробнее о сериале», по умолчанию закрытым в обеих версиях.

### 7.2. Основные сведения

| Поле | Источник / правило | Представление |
|---|---|---|
| Страны производства | `production_countries`; для TV при отсутствии — `origin_country` с явной подписью «Страна происхождения» | Русские названия, все известные страны, без отождествления с регионом релиза |
| Жанры | `genres[].name` | Все валидные жанры, перенос строк; существующий вывод привести к общей компоновке, не продублировать |
| Длительность фильма | Положительный `runtime` в минутах | «2 ч 49 мин»; меньше часа — «45 мин» |
| Длительность эпизода сериала | Положительные уникальные `episode_run_time` | «Серия: 45 мин» либо «Серия: 45–60 мин» при нескольких значениях, без утверждения о точной длине каждой серии |
| Резерв длительности TV | Если `episode_run_time` пуст, но есть положительный `last_episode_to_air.runtime` | «Последняя серия: 56 мин»; не называть её обычной/средней длительностью |
| Объём сериала | `number_of_seasons`, `number_of_episodes` | Сезоны и серии с русскими склонениями; не вычислять общую длительность произведением числа эпизодов и одной длительности |
| Дата фильма | `release_date` либо выбранный региональный релиз, см. ниже | Русский формат даты с корректной подписью; не смешивать даты разных типов/регионов |
| Даты сериала | `first_air_date`, при завершённом сериале валидная `last_air_date` | «Первый эфир: …» / диапазон; последнюю вышедшую серию продолжающегося шоу не выдавать за финал |
| Возрастной сертификат | Для movie — `release_dates`, для TV — `content_ratings` | Только реальный сертификат и его регион; отсутствие не заменяется «0+» |

Русские названия стран и языков получать по ISO-кодам через существующий словарь/поддерживаемый Intl.DisplayNames; предусмотреть безопасный fallback, если локализация недоступна. Не считать исходный язык языком дубляжа или доступной озвучки.

Регион возраста/регионального релиза в первой версии — RU как явная конфигурация отображения, без определения местоположения пользователя. Для фильма брать непустой сертификат RU из release_dates: предпочесть Theatrical (type 3), затем limited theatrical (2), digital (4), TV (6), physical (5), premiere (1); среди одинакового приоритета выбрать запись с валидной датой, при нескольких — наиболее раннюю. Отображать значение источника, не преобразовывать зарубежный сертификат в российский.

Для TV брать непустой rating RU из content_ratings. Если данных RU нет, возрастной badge не показывать; не подставлять NL/US без обозначения. Место для полей не должно оставлять визуальные пустоты.

Если показана дата из выбранного регионального релиза, обозначить её регион и тип («Кинопрокат RU», «Цифровой релиз RU» и т. п.). Если доступна только общая `release_date`, подпись «Дата выхода по TMDB» без утверждения о российской премьере. Код `(NL)` в пользовательском референсе нельзя автоматически трактовать как страну производства.

Дату форматировать как календарную дату, без сдвига дня из-за UTC/local timezone. Пустые/невалидные поля пропускать; нулевые и отрицательные длительности не показывать.

### 7.3. Слоган

- Показывать непустой `tagline` как одну спокойную текстовую строку/абзац перед описанием: меньше заголовка, с умеренным выделением или курсивом.
- Не делать отдельный крупный баннер, карусель, анимацию печати или цитату с выдуманным автором. Уже имеющиеся в источнике кавычки не дублировать.
- Разрешить естественный перенос длинного слогана. Контраст остаётся достаточным в обеих темах; второстепенность не достигается почти невидимым текстом.
- Если русского слогана нет — не показывать блок. Не делать отдельный запрос ради английского fallback и не переводить моделью. Не выдумывать слоган из описания.
- Скриншот с «Новая эра зла» не использовать как источник текста для другой работы и не проверять по нему правдивость сведений фильма.

### 7.4. Второстепенные сведения

В сворачиваемом блоке компактная семантическая таблица описаний (`dl`):

- «Оригинальное название»: `original_title` / `original_name`; не повторять, если оно совпадает с видимым заголовком после нормализации пробелов/регистра.
- «Статус»: локализованное значение `status`; сохранить существующие TV-статусы и добавить фильмы. `Released` → «Выпущен», `Post Production` → «Постпродакшн», `In Production` → «В производстве», `Planned` → «Планируется», `Rumored` → «Не подтверждён», `Canceled` → «Отменён». Не выводить статус из одной только даты. Неизвестное непустое значение выводить как текст источника.
- «Исходный язык»: `original_language`, русское название по коду.
- «Бюджет» и «Сборы»: положительные конечные значения `budget` и `revenue` фильма. Форматировать через Intl.NumberFormat с явным USD, например «165 000 000 $ (USD)». Не конвертировать валюты и не добавлять прибыль или окупаемость. Пометка блока: «По данным TMDB».
- Ноль/отсутствие финансовых данных означает отсутствие сведений, не нулевой бюджет/сборы. Такие строки пропустить. Для TV эти поля в стандартных details отсутствуют: не выводить пустые финансовые строки и не выдумывать значения.
- Если все дополнительные поля отсутствуют/дублируют основные, скрыть пустой блок целиком. Статус сериала не дублировать одновременно в двух местах: учесть текущий вывод при переработке карточки.

### 7.5. Адаптивность и загрузка

- На десктопе основные сведения — компактная строка/несколько естественно переносящихся групп; на телефоне — строки с понятными подписями, без уменьшения шрифта ради помещения в одну строку.
- Разделители «·» декоративны, не остаются в начале/конце перенесённых строк и не становятся единственным способом понять поле. Страны с жанрами не сливаются в неразличимый набор.
- Никакой горизонтальной прокрутки карточки, фиксированной высоты для длинного слогана или обрезки обязательных сведений. Второстепенный блок раскрывается клавиатурой и тапом, показывает своё состояние и остаётся доступен со screen reader.
- Details уже содержат жанры, runtime и другие основные поля: использовать загруженный ответ. Сертификаты можно присоединить через append_to_response (`release_dates` / `content_ratings`) либо загрузить независимо; их сбой не блокирует карточку. Согласовать с существующим append `videos`, не потерять трейлер.
- Не загружать все сезоны и эпизоды только ради длительности сериала; допустимы описанные данные текущего ответа.

## 8. Данные TMDB

Использовать существующий механизм запросов и конфигурацию, не добавлять и не выводить новые ключи в документацию, логи или отчёты.

| Назначение | Endpoint | Основные параметры |
|---|---|---|
| Поиск человека | `/search/person` | `query`, `language=ru-RU`, `include_adult=false`, `page` |
| Имя и фото человека | `/person/{person_id}` | `language=ru-RU` |
| Фильмография | `/person/{person_id}/combined_credits` | `language=ru-RU` |
| Поиск названий и подсказки | `/search/movie`, `/search/tv`, `/search/multi` | `query`, `language=ru-RU`, `include_adult=false`, `page` |
| Основные и дополнительные сведения | `/movie/{id}`, `/tv/{id}` | `language=ru-RU`; использовать существующие details |
| Возраст/региональные даты фильма | `/movie/{id}/release_dates` | Поиск выбранного региона в ответе |
| Возраст сериала | `/tv/{id}/content_ratings` | Поиск выбранного региона в ответе |

Допустимо объединить детали и фильмографию через поддерживаемый `append_to_response=combined_credits`, после проверки реального ответа. Поиск людей не должен запускать загрузку полной фильмографии каждого результата.

Разделение данных:

1. «В ролях» — только записи `cast`.
2. «Режиссура» — только `crew` с `job === 'Director'`. `Producer`, `Executive Producer`, `Writer`, `Creator`, помощников режиссёра и прочие работы сюда не включать.
3. Фильмы — `media_type === 'movie'`, сериалы/телепрограммы — `media_type === 'tv'`.
4. Дедупликация внутри каждого направления по паре `(media_type, id)`. Сохранять разные роли одного человека в одной работе; не создавать повторный постер.
5. Проверять валидность ID и названия; игнорировать неизвестные типы и некорректные записи. Не показывать записи `adult === true`.
6. Сохранить текущую атрибуцию TMDB. Язык `ru-RU` не гарантирует перевода имени, названия или персонажа; выводить предоставленные данные как безопасный текст.

Для определения доступных направлений использовать фактические нормализованные credits. `known_for_department` годится для подсказки, но не заменяет проверку credits.

### Телевизионные выступления

Рекомендация первой версии: по умолчанию скрывать TV-записи жанров Talk (`10767`) и News (`10763`). В разделе сериалов — переключатель «Включить телешоу», поясняющий, что он добавляет ток-шоу и новости. После включения обновляются список и счётчик.

Это фильтр конкретных жанров, а не гарантия «только художественные сериалы»: документальные работы и записи без жанров могут остаться. Не отбрасывать всё участие `Self` по неточному сравнению строк. Документальные фильмы, анимация, озвучка, камео и будущие работы остаются, если проходят остальные правила.

### Сортировка

- Популярные: `popularity` по убыванию.
- Новые: валидная дата выхода/первого эфира по убыванию; неизвестные даты в конце. Будущие даты не скрывать и отмечать «Скоро».
- По рейтингу: сначала работы с действительной оценкой и ненулевым числом голосов, `vote_average` по убыванию; при равенстве — число голосов. Без оценки — в конце. Показывать число голосов доступным текстом, не объявлять эту сортировку объективным «топом».
- При равенстве основных значений использовать стабильный дополнительный порядок. Переключение вкладок не должно хаотично переставлять карточки.

## 9. URL, история и возврат

Рекомендуемое расширение существующей схемы, которое исполнитель может уточнить без изменения поведения:

- Поиск: `?mode=search&st=person&q=Брайан%20Крэнстон&page=1`.
- Человек: `?view=person&id=17419&role=acting&ptab=tv&psort=popular`.
- Телешоу: дополнительный `shows=1`; без параметра выключены.

Не переиспользовать `pt` под вкладку человека: он уже относится к подбору фильмов/сериалов. Новые параметры валидировать; неизвестные значения заменять безопасными defaults. Старые URL фильма, сериала, каталога и «Моё» продолжают работать.

Хранить контекст возврата в истории/сессионном состоянии маршрута: исходный экран, запрос, страницу выдачи, вкладку, сортировку, показанную порцию и прокрутку. Не записывать отдельную историю посещений в постоянное хранилище.

Проверить цепочку «каталог → фильм → человек → другая работа → Назад → человек → Назад → исходный фильм → Назад → каталог» и Back/Forward браузера. Для открытой напрямую страницы без внутреннего предыдущего экрана предоставить явный переход «К поиску людей», а не отправлять пользователя на случайный внешний сайт через безусловный `history.back()`.

## 10. Состояния и доступность

| Состояние | Поведение |
|---|---|
| Загрузка | Понятный индикатор/скелет без ложного нулевого счётчика; стабильная компоновка |
| Нет результатов поиска | «Люди не найдены. Попробуй другое написание имени»; запрос сохраняется |
| Пустая фильмография | «В TMDB нет фильмов с актёрским участием» или другая подпись по текущему направлению/типу |
| Всё скрыто фильтром телешоу | Объяснить фильтр и дать включить телешоу |
| Другие профессии без поддерживаемых работ | Показать имя/фото и объяснить, что доступны актёрские и режиссёрские работы, которых в TMDB пока нет |
| Ошибка API/сети | Отличать от пустого списка, дать «Повторить», сохранить запрос и настройки |
| Нет/сломано фото или постер | Заглушка; имя, участие и переход остаются доступны |
| Некорректный ID / 404 | «Человек не найден» и безопасный переход к поиску |
| Офлайн | Честное сообщение о необходимости сети; не обещать доступность полной фильмографии офлайн |
| Уход или новый запрос | Отмена прежнего запроса и защита от позднего ответа, который мог бы заменить новый экран |

Ссылки на людей доступны с клавиатуры, имеют видимый фокус и понятные названия. Вкладки реализовать по выбранному доступному паттерну: при `role=tab` обеспечить связанный panel, `aria-selected` и клавиатурное переключение. Состояние переключателей озвучивается. После перехода фокус идёт в заголовок экрана, при возврате — к исходному элементу, когда он существует. Сохранить поддержку reduced motion.

## 11. Производительность и сохранность

- Живой поиск выполняется с debounce и минимальной длиной из раздела 4; Enter применяет его сразу. Подсказки и основная выдача используют один ответ и объединённые запросы.
- Не создавать отдельный запрос на каждую карточку выдачи или постер фильмографии. Использовать метаданные credits и существующий механизм изображений.
- Лениво загружать изображения; использовать текущие безопасные функции URL, подходящие размеры и `srcset`. Не загружать `original` без необходимости.
- Допустим небольшой ограниченный кеш деталей/credits на время сессии; не хранить всю фильмографию постоянно и не добавлять миграцию «Моё».
- Сбой нового сценария не должен ломать каталог, состав, трейлер или личные списки.
- При выпуске обновить версии ресурсов и PWA-кеш согласно текущему механизму проекта. Не удалять пользовательские данные ради обновления.

## 13. Проверки и критерии приёмки

### Автоматические

- Нормализация людей и credits: дубли, несколько ролей, смешанные media types, строгое выделение Director, отсутствующие поля, неизвестная профессия, некорректные изображения, adult.
- Фильтр телешоу, счётчики и сортировка: неизвестные/будущие даты, отсутствующие оценки, стабильный порядок.
- Поиск: нужный endpoint, русский язык, непустой query, пагинация, include_adult=false, ошибки и отмена.
- Живой поиск: debounce с управляемым временем, минимальная длина, очистка, IME, смена категории, отмена и поздний ответ, отсутствие дублей запросов подсказки/выдачи/Enter. Проверить историю без шага на каждую букву и восстановление query после карточки.
- Метаданные: movie/TV duration, пустой episode_run_time и явно обозначенный резерв последнего эпизода, отсутствующие/нулевые деньги, статус, локализация страны/языка, календарная дата без timezone-сдвига, RU certification и отсутствие чужого fallback, отсутствие/длинный tagline, отсутствие дублей полей.
- URL: новые параметры, прямой вход, defaults, некорректные значения и совместимость существующих ссылок.
- Релевантные проверки доступности и навигации; общий `npm run check` и `npm test` свежего проекта проходят. Не подменять ручную проверку возврата только тестом parseState.

### Ручные в браузере с реальным TMDB

1. Поиск русским и латинским написанием имени; конкретные результаты зависят от источника. Не обещать собственную транслитерацию. Проверить пустой запрос, отсутствие результатов и несколько людей с одинаковыми именами. Для воспроизводимой коллизии использовать fixture, если актуальная выдача не даёт устойчивого примера.
2. Актёр с фильмами и сериалами, режиссёр с обоими типами работ, человек с двумя направлениями, человек с отсутствующим фото и человек с пустым разделом.
3. Проверить повторы, озвучку и ток-шоу на реальной фильмографии Брайана Крэнстона. Сверить видимые работы с ответом TMDB, а не с памятью о его карьере.
4. Сортировки, счётчики, «Показать ещё», добавление работы в «Моё» и отсутствие потери существующих списков.
5. Полная цепочка переходов, Back/Forward, перезагрузка и открытие прямой ссылки в новой вкладке.
6. Ошибка, повтор, offline и медленный ответ после ухода — с управляемыми сетевыми условиями/fixtures, если живой сервис не воспроизводит их.
7. Ширины 320, 390, 768 и 1440 px, обе темы, длинные имена, клавиатура, видимый фокус, отсутствие горизонтального переполнения и обрезанных кнопок. Подготовить скриншоты компьютера и телефона.

8. «Инте» → подсказки с «Интерстеллар» и другими фактическими совпадениями; быстрый набор/удаление; выбор стрелками/Enter, тапом, Escape, очистка, вставка и смена категории во время запроса. Enter без выбранной подсказки оставляет полную выдачу, без повторного запроса. Проверить область нажатия и завершение blur/click, чтобы вариант не исчезал раньше выбора.
9. Автоматическое обновление выдачи без кнопки «Поиск» на компьютере и телефоне, с открытой клавиатурой, без скачков фокуса/прокрутки и вспышек устаревших результатов. Enter/клавиша поиска мобильной клавиатуры работают как дополнительное действие.
10. Сверить страны, жанры, длительность, даты, сертификат, слоган и дополнительные сведения фильма/сериала с текущим TMDB. Проверить отсутствующий сертификат RU, оригинальное название, равное основному, нулевые бюджет/сборы, длинный слоган и пустые длительности. Полный сезон не загружается ради одного поля.

### Готовность к выпуску

- Дизайн согласован; сценарии из раздела 3 реализованы; проверки пройдены или ограничения явно перечислены.
- Обновлены релевантные feature-документы, manifest и evidence по текущим правилам harness. Не переписывать CAST-001 так, будто его прежний выпуск уже включал страницы людей.
- Есть PR с русским заголовком и описанием, понятный diff и доказательства проверки.
- Merge/push в master и production требуют отдельного явного разрешения Алексея на этот scope. Ранее данное разрешение на публикацию состава не распространяется автоматически на эту функцию.
- После разрешённой публикации отдельно проверить Pages deployment, публичные поиск/страницу человека и обновление ресурсов. Локальные тесты не являются доказательством публикации.
- Проверка физического iPhone Safari и установленной PWA отмечается отдельно. Эмуляцию не выдавать за проверку реального устройства.

## 14. Не входит

Биографии и энциклопедия людей; награды и родственники; фильмографии продюсеров/сценаристов; подбор по сочетанию нескольких актёров; рекомендации на основе личности; AI-автодополнение и исправление опечаток собственным сервисом; собственная транслитерация; внешняя аналитика; аккаунты; сервер; офлайн-зеркало; перевод данных моделью; новый визуальный стиль; вычисление полной длительности сериала через загрузку всех эпизодов; геолокация; конвертация валют и вывод прибыли.

Возможное продолжение — только после проверки базового сценария: поиск работ сразу нескольких людей, дополнительные профессии и более сложные фильтры. Не добавлять их в этот выпуск без решения Алексея.
